# Design decisions log

Append-only. Every change to `code/common.py`, the feature sets or the evaluation must have an entry here, dated, **before** the test set is unsealed. After the freeze, entries may only add sensitivity analyses. They may not change the primary specification.

| Date | Decision | Why | Changed results? |
|---|---|---|---|
| 2026-10-06 | Topic switched from "listing-filter counts" to forecasting recorded Class C violations | Counting how many options remain after filtering is a product feature, not a research contribution. A forward-looking warning with a validation standard tests whether a housing-information product adds anything a renter cannot get by looking up the record. | — |
| 2026-10-06 | Outcome = any new Class C violation by *inspection date* within 6 months | Class C means "immediately hazardous". Inspection date is when the condition was observed. Approval date governs only when information becomes *known*. | — |
| 2026-10-06 | Features use only records approved ≤ t − 30 days; complaint months must end ≤ t − 30 days | Publication-lag buffer. 0- and 60-day sensitivity planned. | — |
| 2026-10-06 | `currentstatus` never used in the main analysis; dismissed violations kept | Status is today's value, so it leaks. Whether a violation would later be dismissed was unknown at t. | — |
| 2026-10-06 | Register attributes (units, stories, program) excluded from features | They are current snapshots, not values as of t. | — |
| 2026-10-06 | Complaints downloaded aggregated to building × month × category × type | 7M problem rows otherwise. Monthly resolution is coarser than daily, so complaint "90-day" windows are 3 calendar months. | — |
| 2026-10-06 | Problem type from HMC order number via keyword rules (`02_order_categories.py`) | 126 order numbers. Avoids downloading the free text for 2M rows. The lookup table is reviewable by hand. Generic "nuisance" order 510 (~5%) stays in `other`. | — |

| 2026-10-06 | **Definitional break, 2019.** Class C pest violations rose from ~0.7k/yr (2017–18) to 46.7k (2019), and doors/egress from 3.9k to 19.2k. This is consistent with a reclassification of these conditions as Class C (the legal source is still to be confirmed). All training origins (2020+) have outcome windows after the break, but 2-year lookbacks for the 2020 origins straddle it. Planned sensitivity: an outcome restricted to the categories that were stable across the break (heat/water, lead, structural, mold/leak, gas/electric, detectors). | The outcome definition must be stable across train and test. | Adds a sensitivity analysis |
| 2026-10-06 | **Added M2d = M2c + district context** (`cd_share_c365`, `cd_share_c90`, `cd_mean_comp365`), computed per community district × origin from in-scope buildings' features at *t*. It is a fifth compared model; M2c is kept. | Dev results showed district O/E tracking the district event rate (ρ = 0.80, range 0.33–1.13) for the place-blind models. Decided before the freeze, at the author's request. Dev result: ρ 0.80 → 0.10; districts with \|O/E−1\| > 0.2 from 8 to 2; held-out ΔBrier −0.0007 [−0.0011, −0.0003]; but districts with < 10% recall at a citywide cut rose from 2 to 8. | Adds a model and a contrast; earlier models unchanged |
| 2026-10-06 | **Primary warning rule = district-relative**: flag the top 10% of buildings *within each community district* at each origin (buildings without a district use the citywide cut). The citywide top-10% rule is reported alongside it. **Product model = M2d.** Both are in `common.py` and in the spec hash. | Author's decision after the M2d dev results: a calibrated citywide score concentrated warnings in high-rate districts (8 districts with < 10% recall). Dev result for M2d with the same 10% budget: districts with recall < 10% go from 8 to 0, minimum district recall from 0.00 to 0.20, and recall IQR from 0.30 to 0.15. The cost is overall recall 0.371 → 0.321 (−13.5%), precision 0.788 → 0.682, and minimum district precision 0.125. | Adds the warning-rule comparison; model fits unchanged |
| 2026-10-06 | Precision/recall at 10% are now computed **per origin** (the budget applies at each prediction date), not pooled across origins. | Needed for the multi-origin test. Dev numbers are unchanged because dev has one origin. | No (dev) |

Primary warning-rule comparison: M2d, district-relative vs citywide. | 2026-10-06 | **Secondary (post-freeze): ACS context, M2e** = M2c + 8 ACS 2014–18 tract features + missing flag (`09_fetch_acs.py`, `10_acs_context.py`). The vintage was chosen because it was released before the first origin. The procedure mirrors the frozen test stage. | Tests whether non-enforcement place context avoids M2d's drift. Uses test outcomes, so it is exploratory. Result: ΔBrier vs M2c −0.0010 in-district and −0.0009 held-out; districts > 20% off fell from 20 to 9; temporal drift unchanged. | Secondary only |
| 2026-10-06 | **Secondary (post-freeze): rolling recalibration** (`11_recalibration.py`). Model fits are untouched; the score→probability map is refreshed on the origin 12 months before each test origin (intercept, Platt, Platt + shrunken per-district offsets, λ = 100 fixed a priori). The 2023-07 buffer origin was built for this purpose. Re-fits were verified to reproduce the frozen predictions exactly. | Tests whether scheduled recalibration repairs the decay. Result: M2c O/E at 2025-07 rose from 0.87 to 0.92; district offsets cut district error by about a third; the best configuration was M2e + rolling district offsets (mean district error 0.065, 3 districts > 20% off). | Secondary only |
| 2026-10-06 | **Secondary (post-freeze): partial-window recalibration** (`12_partial_recal.py`). The origin t−6m (≈5 months observed by t−30d) is completed with a chain-ladder factor estimated at t−12m; intercept and district shifts are made toward the completed rate. | Tests whether the one-year lag of the full-window refresh causes the residual decay. Result: completed rates were accurate (mean abs error 0.005) but calibration did not improve. Diagnostic: event rate flat while mean prediction rose 0.240 → 0.272, i.e. the drift is input inflation. | Secondary only |
| 2026-10-06 | **Secondary, added after seeing the diagnostic above: anchoring.** Shift the intercept so the mean prediction over origin t's own in-district rows equals the completed rate. It uses t's features (known at t) and no outcome from t's window. | Most exploratory result in the paper; explicitly data-driven. Result: pooled O/E 0.99 for all models; M2d + anchor + district offsets gives mean district error 0.028 and 0 districts > 20% off. | Secondary only |
| 2026-10-06 | **Secondary (post-freeze): sensitivity grid** (`13_sensitivity.py`): lag 0/60, no_dismissed (leaky), stable-category outcome, + Class A/B history (new fetch job `violations_ab`, aggregated by building × inspection month), 3- and 12-month horizons. The baseline row reproduces the frozen test exactly. | Pre-listed sensitivity analyses. All pre-specified conclusions hold in every variant. The H1 gain halves with the stable-category outcome. | Secondary only |
